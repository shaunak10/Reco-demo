# Model card - `reconai-column-ranker`

Local column-mapping ranker used in Step 4. Written for the DPIIT evidence pack: it says what is a model, what is not, how it was
trained and measured, and where it is weak. Measured numbers live in [`docs/results/step4_column_mapping.md`](../docs/results/step4_column_mapping.md)
(regenerate with `python ai/eval_mapping.py --write`).

## Purpose
Suggest which canonical field (`TransactionRef`, `Amount`, `Currency`, `TxnDate`, `SettlementRef`, `Fees`, `Status`) each column of an
uploaded ledger / gateway / bank file feeds, or that the column should be ignored, with a confidence and the evidence behind it.
**It only suggests.** An operator confirms every mapping; the AI never saves a mapping or imports a row, and reconciliation works when it is down.

## What is model-assisted, and what is not
| Part | Kind |
|---|---|
| Per-column scores over 7 fields + IGNORE | **Trained model** (multinomial logistic regression) |
| Heading similarity features (RapidFuzz token / ratio similarity, character n-gram TF-IDF cosine, keyword purity) | Feature extraction feeding the model |
| Value-profile features (share of values that parse as dates / amounts, uniqueness, running-balance behaviour, relative size among money columns, ...) | Feature extraction feeding the model |
| One field per column and one column per field (Hungarian algorithm), minimum probability 0.30 | Deterministic rule |
| Per-source masks (a bank file never offers Fees or TransactionRef; a ledger never offers SettlementRef or Fees) | Deterministic rule |
| Confidence band (high >= 0.80, medium >= 0.50, else low) | Deterministic, recomputed by the C# app |
| "Reasons" text | Deterministic description of measured evidence, **not** the model's internal weights |
| Validation of the whole answer (allowed fields, ranges, duplicates, heading match) | Deterministic, in the C# app |

Not an LLM and not a pre-trained network. A simple fuzzy match is **not** presented as ML: the heading-only fuzzy baseline is measured separately for comparison.

## Training data
- 415 author-written headings (`ai/data/header_corpus.json`): 7 canonical fields with 12-49 alternative labels each, plus 187 non-reconciliation headings in 18 groups (names, phones, balances, narrations, ...).
- Values are generated by seeded synthetic generators that imitate the *shape* of recharge / gateway / bank data. 660 synthetic files, 5,028 columns. No real customer data.
- Leave-one-out heading features: while training, a heading's own corpus entry is hidden, so the model sees the same "never seen this exact heading" situation as a real upload.
- Deterministic: fixed seeds; the model version is a hash of the corpus, hyper-parameters and the source of every module that shapes the model.

## Evaluation (see the results file for numbers)
1. Grouped cross-validation on the training files (whole headings held out together).
2. **Held-out headings** (`ai/data/eval_headers.json`, never used for training; a test asserts zero overlap) in freshly generated files, with a heading-only baseline and stress tests (headings only, values only, typos).
3. **The real demo datasets** (3 scenarios x 3 sources) against the human-authored `ground_truth_mapping.csv`; their headings are also excluded from training (asserted by a test).
4. Live end-to-end tests (real service, real upload, real import) in `tests/ReconAI.Tests/Ai/LiveAiTests.cs`.

## Known limitations (read before claiming anything)
- **Same author, same mental model.** Training headings, evaluation headings, the data generators and the demo datasets were all written by one person. High accuracy here shows the pipeline works and generalises to unseen *strings*; it is **not** evidence of accuracy on other companies' real exports.
- Values alone are weak evidence (47% in the stress test): the model leans on headings. Unusual or misleading headings lower confidence but can still mislead.
- Seven fields only; several date columns, multi-line headers, merged cells, non-INR amounts and non-English headings are not modelled.
- Confidence is the model's probability after the one-to-one constraint; it has not been calibrated on independent real data.
- Cross-tenant learning is deliberately absent (deferred in the plan): the model never learns from a customer's confirmed mappings.

## Operational facts
- Libraries: NumPy, SciPy (BSD-3), RapidFuzz (MIT). The model is implemented in NumPy/SciPy because this machine's Windows Application Control policy blocks parts of scikit-learn's compiled extensions; no policy was changed.
- Starts in under a second from a cached weights file (`ai/.cache/`, derived and git-ignored), otherwise trains in about 8 s.
- The service listens on loopback only, never logs or stores sample values, and caps input (60 columns, 50 samples of up to 200 characters each).
