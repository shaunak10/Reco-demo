# Step 4 - AI column mapping: measured results

Generated by `ai/eval_mapping.py` on 21 Oct 2026. Synthetic data only. Failures are listed, not hidden.

## What was measured

- **Model:** `reconai-column-ranker` version `08592671` - multinomial logistic regression (L-BFGS, NumPy/SciPy). Trained at start-up on 5,028 columns from 660 synthetic files built from 415 author-written headings. No pre-trained weights; no LLM. Licences: RapidFuzz MIT, NumPy/SciPy BSD-3.
- **Which parts are model-assisted:** the per-column scores. **Deterministic, not model:** the one-to-one assignment, per-source masks, confidence bands and the reasons text.
- **Leakage control:** the heading strings used for evaluation (held-out set and the demo datasets) never appear in the training corpus (asserted by tests).

## A. Grouped cross-validation (headings held out together)

5,028 columns, 415 distinct headings, 5 folds: **accuracy 94.2%**, log-loss 0.206. Slightly optimistic: held-out headings still sit in the similarity index of the other folds.

## D. Runtime and memory

- Training at start-up: 8.06 s. Suggestion latency over 9 real files: median 42 ms, max 47 ms.
- Process memory after loading and evaluation: 117.8 MB.

## Limitations

- Training and evaluation headings were all written by the same author, so real-world headings from other companies may behave differently.
- Only seven canonical fields; unusual layouts (several date columns, multi-line headers, merged cells) are not modelled.
- Suggestions are never applied automatically: an operator must review and confirm every mapping.
